# 研究年度与实际数据覆盖修复

用户复现：问题写为2023—2025年，但工作区仍显示2023—2024且没有缺失提示。根因是旧版本只连接2024年年报的当期/比较数，任务默认期间、模型输入、报告说明均写死2023—2024，问题文本没有进入期间校验。

本次修复：

- 创建研究增加起始/结束年度；研究问题中的年度范围可同步选择器。服务器校验范围并保存请求年度。
- 既有研究没有请求年度记录时，从原问题识别，无需修改或重建用户任务。
- `periods.py` 逐家公司、逐年检查最新有效数据批次。界面和报告区分“研究年度”和“实际数据”。缺失2025时持续显示部分覆盖，不把年报披露日期2025当成2025年度数据。
- 手动导入新年度数据后，根据真实导入行重新计算覆盖；不固定写2023—2024。
- 数据不全时在模型请求和额度消耗前阻止生成完整期间研究。实际已取得数据仍可以比较和导出，Markdown/Excel均标明缺失年份。
- 原2024年年报及2023比较数的来源登记内容保持其真实期间，不把文件改名冒充2025年年报。

验证：65项本地检查通过（原57项+新增8项）；8项浏览器场景通过，使用真实已获取年报的隔离数据库副本，无新增模型调用。导出的Excel另检查研究/实际年度与缺口说明，财务表仅有真实2023/2024四条记录。证据位于 `test-results/period-fix/`，单元检查摘要为 `test-results/period-fix.json`。

能力边界：当前自动获取仍仅接入茅台/五粮液2024年报及2023比较数，本次没有接入2025年年报或全市场任意年份检索。研究范围可以设置，覆盖与缺失会如实显示；新增年份可导入带可核验出处的真实财务数据。
