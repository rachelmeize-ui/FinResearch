# 腾讯业务资料获取修复 · 2026-11-22

用户研究 `5188c85328274c63` 为腾讯与网易2023—2025年业务竞品研究。最初腾讯四个维度全部“资料不足”，网易有官网摘录。原始任务与获取记录保留在本机测试结果中。

## 实际原因

1. 巨潮识别结果包含证券代码与市场，不包含官网。腾讯已识别为00700，但资料发现阶段没有官网，域名白名单为空，因此没有尝试下载腾讯正文。网易已有官网入口，故表现不同。
2. 免费 Bing RSS 在该次长问题查询中返回不相关内容，旧记录只写“已查找”，掩盖了没有可信官方候选的事实。
3. 实际腾讯年报约4.4—6.8 MB。本机下载4.4 MB文件实测约一分钟；旧下载器整个文件25秒截止，中途数据未被当成成功文件保存。
4. 网页和PDF正文提取是两条不同路径；此前业务研究只读当前网页，不查年报索引。较短中文正文也可能被35字符的英文式阈值遗漏。

## 修改

- `entities.py`：以已识别证券ID `cninfo:00700` 绑定已验证腾讯官网、业务页、官方年报索引。腾讯音乐等同名候选不会继承该域名。登记的是资料入口，没有硬编码业务结论或财务数值。
- `business_research.py`：从实际下载的官方索引按所选年度发现PDF，排除中期和其他年度报告；下载后检查PDF及封面年度，逐页提取。证据保留原文、报告年度、PDF页码、哈希、发现索引。网页仍标为当前网页，不冒充历史快照。
- 实际下载又暴露中文CFF字体映射错误。增加 `pdfplumber/pdfminer` 备用解析与独立文本缓存，支持中文数字年度标识；不覆盖旧财务解析缓存，无法确认年度时仍拒收。生产依赖在 `requirements.txt` 登记。
- 年报采用240秒有界下载窗口，仍遵守25 MB文件上限；`source_io.py` 为长文件保留15秒单次读取容限，普通请求保持原时限。请求来源地址按目标站点生成，不再固定为巨潮。
- 不相关搜索结果明确记为未采用；缺少确认官网、索引失败、逐年下载或封面校验失败分别登记。
- 排除“了解更多”等行动文案，支持简繁中文关键词，优先带年度页码的正式报告摘录；不以未经核验的财务金额作为业务结论，不调用大模型。
- `research_pipeline.py` 与 `engine.py`：业务任务使用业务完成/缺口状态，彻底没有可用证据时阻塞；保留原任务及历史记录。

## 验证与边界

运行 `scripts/verify_business_sources.py` 执行真实外部下载与逐页引文核对；`scripts/browser_business_sources.mjs` 在原研究中重新执行后端流程，复用实际下载缓存，并检查浏览器证据、刷新和实际报告下载。两者均禁止用模拟金融数据或付费模型替代。

单元测试 `tests/test_business_discovery.py` 覆盖主体绑定、年报年份/官方域名/完整报告过滤、错误封面拒收、下载窗口、无官网与无相关结果、导航文案排除及中文页码引文；这些构造输入测试不能代替真实外部验证。

腾讯接入属于已验证来源目录的扩充，不代表所有港股已有通用财务解析，也不代表所有企业官网均能自动确认。业务结果仍是带来源的确定性原文摘录，不能声称为AI完成的综合分析；部分英文来源和信息缺口会保留。没有新增付费模型调用。
